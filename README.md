# Инструмент «Падежный фильтр» v1.2

**Метод датированной записи. Переносимый носитель-инструмент для верификации утверждений в диалоге с ИИ.**

* **Автор метода:** Ирина Ветлугина (Самара)
* **Держатель ключа:** пользователь (человек, проводящий сверку в диалоге с ИИ)
* **Статус:** `[Р]` — рабочая версия (испытана прогонами №1–№5)

---

## О чём этот инструмент?

Без формулы падежи — просто грамматика. С формулой — строгий фильтр для проверки записей, гипотез и утверждений:
* **«Мама мыла раму»** — проходит (есть исполнитель, действие, объект и оплата тактами).
* **«Рама мыла маму»**, **«рама мыла раму»**, **«мама мечтала помыть»** — не проходят: кресло исполнителя оплачено не тем или граница творца не пересечена.

Инструмент **не решает задачи** за пользователя и не ищет «абсолютную истину». Он работает как строгий бухгалтер: разбирает записи о событиях и задачах, отделяет реальные акты от прогнозов и отлавливает подмены («зоопарк» ошибок).

## Как пользоваться (Быстрый старт)

1. Откройте файл [`case-filter-v1.2.md`](./case-filter-v1.2.md) и скопируйте его содержимое целиком.
2. Вставьте текст в начало нового диалога с любой LLM (ChatGPT, Claude, Gemini, Алиса, DeepSeek и др.).
3. Подайте любую запись или список утверждений командой:
   ```text
   ПРОГОН: [текст вашей записи]
   ```
4. Получите структурированную **карточку записи** по протоколу и краткое пояснение сразу под ней.

> **Важно:** ИИ выступает только как носитель-исполнитель. Ключ сверки по датированным окнам всегда остаётся у человека.

## Основные команды

* `ПРОГОН: [текст]` — разбор записи по карточке с пояснением.
* `ПРОГНОЗ: [Ê] окно [дата]` — регистрация кандидата до свершения акта.
* `СВЕРКА: [Ê против факта E]` — закрытие ставки по наступлении даты окна.
* `СВОДКА` — вывод накопленных ошибок оператора/модели (`О1–О3`) за сессию.
* `АБЛЯЦИЯ: [клетка]` — испытание дисциплины фильтра с исключением указанной клетки.

## Структура репозитория

## Как поучаствовать в тестировании

Инструменту нужны **независимые слепые прогоны** на разных языковых моделях от носителей, ранее не знакомых с системой.
Если вы провели прогон и нашли сбой в классификации (`О1`), чтении (`О2`) или записи (`О3`), пожалуйста, откройте **Issue** в этом репозитории и приложите лог диалога.
